# AI Video Studio：产品方向与交付约束

日期：2026-11-15
状态：用户已确认产品原则；技术默认值与里程碑安排为建议稿，待文档评审。本文不代表功能已经实现，也不授权付费调用。

## 1. 已确认的初衷

**一键生成可观看的初稿，人工按需精修，修改后局部重做，最终可靠导出。**

模型只能生成几秒到十几秒，是系统需要分镜、编排和剪辑的原因，不是要求用户逐镜头操作的理由。系统承担重复劳动，人保留审美判断和创作控制。

北极星目标：用户输入创意、目标时长及预算，系统产出可编辑的完整影片；失败能恢复，费用可解释，满意的素材不因局部修改而重新付费。

下一产品验收目标：**预算约束下，自动产出一部完整、可编辑、可恢复的 60 秒初稿。** 60 秒是阶段验收目标，最终仍面向 3–5 分钟作品。

## 2. 用户体验契约

### 2.1 自动初稿

用户输入创意、语言、时长，选择制作配置并确认一次运行预算。系统依次完成需求解析、故事板、必要参考图、短镜头生成、技术检查、旁白、配乐选择、字幕、时间线和导出。

- 正常成功路径不要求逐镜头、逐边界帧点击确认。
- 默认先预估和展示制作范围；没有运行授权不触发付费 API。
- 初稿不意味着电影级质量保证；低置信度软性问题列入待精修清单。
- 缺少必需素材、硬性检查失败且重试额度耗尽、预算不足或远程提交结果未知时，进入可恢复的阻塞状态，明确下一步。
- 不以空白镜头、静音旁白或未完成状态冒充成功。
- 可选环境音、SFX、付费视觉评审失败可以降级，必须在报告中明确列出；旁白、背景音乐、字幕是标准 60 秒验收配置的必选项。

### 2.2 按需精修

用户可以修改故事板、替换素材、重做单镜头、调整剪辑区间和顺序、修改音频与字幕、比较版本并撤销选择。系统先说明影响范围、可复用素材和新增费用，再执行。

只改字幕：不调用视频模型；只换音乐：不调用视频模型；重做一个镜头：不自动重做全片；参考角色发生变化：标记受影响的素材，允许用户明确保留旧版本。

### 2.3 精细制作模式

现有 Guided 的角色、分镜和边界帧人工确认流程继续服务于需要精确控制的用户。

自动模式与精细模式共享素材、任务、账本和渲染核心。自动模式不能通过伪造“人工已确认”记录来绕过旧流程；必须记录选择来源为 `system` 或 `human`，并使用独立的初稿就绪条件。

切换模式不删除素材、不重置任务，不追溯性改变已经授权的范围。

建议实现为统一 Project/Run 模型上的 `production_mode=automatic|guided`，而不是把自动项目退回 legacy 分支或给 Guided 写入假的人工确认。M2 引入带 `actor=system|human` 的选择/决策记录，历史确认映射为 human；M3 从生成和渲染核心抽取共同的素材有效性检查，由模式策略额外决定是否需要人工确认。角色与边界服务可复用，但其人工门槛不能散落在共享底层。具体表名/API 在 M2 详细计划冻结。

## 3. 建议采用的技术默认值

以下是本轮规划的工程建议，不是用户逐项指定的技术要求。

| 决策 | 默认选择 | 理由 / 重新评估条件 |
|---|---|---|
| 部署范围 | 单用户、本地或单机部署 | 多用户服务另立范围；当前 API 不具备公网服务条件 |
| 数据库 | 先保留 SQLite，增加版本化迁移 | 多进程写入/锁竞争实测不满足需求时再评估 PostgreSQL |
| 调度 | 独立本地 Worker + 持久化 Job、租约和事件 | 不把内存线程池当作任务真相；多机需求出现后评估队列服务 |
| API | REST；先可恢复状态查询，再按需要增加 SSE | SSE 是体验增强，不负责恢复 |
| Provider | 保留共享 core，先一个真实视频 Provider 通过验收 | 适配器数量不能代替真实可用性 |
| 首个自动模式 | 独立镜头纪录片/风景短片 | 先闭合全流程，角色故事沿用精细模式并在长片阶段加强 |
| 参考控制 | 按镜头需求启用，不强制所有相邻镜头共享边界 | 连续动作与正常剪切需要不同策略 |
| 配乐 | 本地已配置、来源清楚的音乐库自动选择 | 首版不依赖新增音乐生成 API；空库在运行前阻塞标准配置 |
| 导出 | 60 秒产品验收：1920×1080、24fps、H.264/AAC | 720p 可作为代理预览；放大到 1080p 不宣称素材原生 1080p |
| 技术重试 | 每镜头最多 2 次生成尝试，包含首次 | 只对确定可重试的失败/硬性不合格，且必须有剩余额度 |
| 软性评审 | 建议与证据，不自动无上限重拍 | 用户授权的后续策略必须有最大尝试数与总预算 |
| 预算 | USD、统一项目账本、金额使用整数微美元 | 预留/估算不等于供应商硬性消费上限 |

## 4. 必须守住的工程边界

### 4.1 任务与外部副作用

任务、尝试和远程任务分开：一次镜头制作可以有多个尝试，每次付费提交有自己的请求身份、输入快照和费用记录。

- 提交前，原子保存尝试、指纹和费用预留；重复请求返回同一个尝试。
- 提交结果未知进入 `UNKNOWN_REMOTE_STATE`，保留预留，不自动重发。
- 已知 remote ID 的恢复只能查询/下载，不能重新提交。
- Worker 租约失效允许接管本地工作，但不等于允许重复外部付费副作用。
- 403 等明确配置/权限拒绝阻塞；429 依据结构化错误与 Retry-After 退避。不能凭所有异常使用同一处理策略。
- 暂停停止新提交；已在远程运行的任务继续记录和对账。
- 取消停止本地后续任务，远程取消按 Provider 能力尽力执行；不承诺退款或停止已产生的账单。
- 硬性校验失败先区分本地处理可修复与必须重新生成，避免拿视频 API 重试解决下载故障。

状态命名及数据库字段在 M1 的详细设计中冻结。上述行为是不可更改的验收语义。

### 4.2 费用统一

账本覆盖分镜 LLM、图像、视频、TTS、视觉评审；本地渲染时间和存储量独立记录，不伪装成供应商账单。

每条费用关联 project、run、job、attempt、provider、model、计价版本；区分预留、估算、已确认实际费用和待对账。

可提交额度使用“尚未结算的预留 + 已结算实际费用 + 尚无实际账单的估算”计算，同一尝试不能重复相加。不确定失败的预留不能自动释放；明确不收费的结论需有证据。低估造成的实际超支要记录并阻止新提交，不能篡改成未超支。

项目总额度、运行授权额度同时校验。授权覆盖本次约定的各阶段和有限技术重试；更换高价模型、扩大制作范围或超额必须获得新的授权。精修的新增费用属于新授权。

历史数据没有的实际账单标记 `unknown`；已有预留只迁移一次，不补造金额。

真实试片金额不在本 Roadmap 中预授权：M3 开始前提交运行配置，列出 provider/model、T2V/I2V、各阶段计价、每次尝试预留、试片总额度及 60 秒总额度，由用户确认。额度是不可自动越过的本地新提交门槛，不保证供应商最终账单不超估算。自动化用固定虚拟费率测试精确边界，无需等待真实报价。

首个真实验收默认选择独立镜头 T2V，具体模型在 M3 预检后选定，不能把仓库中的能力常量当作实时可用证明。若改用 I2V，必须把参考图步骤、费用与数据上传范围纳入同一验收配置；M3 不要求所有镜头使用共享边界。

音乐库建议为配置项 `STUDIO_MUSIC_LIBRARY` 指向的目录，清单记录文件、哈希、来源、用户确认的使用范围及风格/时长标签。仓库已有音乐不自动视为已获确认的验收素材；M3 开始前由用户提供或确认至少一首可用音乐。未配置属于输入阻塞，不触发自动联网下载。

### 4.3 编辑与版本

目标结构为 Project → CreativeBrief → StoryboardRevision → Scene → Shot，并关联不可变素材、TimelineRevision、Audio/SubtitleRevision、RenderSnapshot。

Scene 表达地点、时间与叙事功能；Shot 表达生成单元；Timeline Clip 表达剪辑区间，不把裁剪直接写回原视频。

基本时间线先支持单视频轨、独立音轨、字幕及 `source_in/source_out`。复杂多视频轨、特效合成后置。

修改通过依赖图标记受影响节点；不删除旧版本。重渲染从固定快照读取素材和参数，不读取正在变化的“最新选择”。

承诺是可复现编辑输入与导出配置，不承诺远程生成模型再次调用会得到字节相同结果。

### 4.4 质量与证据

技术质量检查负责文件可解码、时长、尺寸、音轨及黑屏/冻结等证据；静态或黑场可能是创作意图，语义相关阈值必须由配置定义，不能无条件重拍。

VLM 仅提供证据和建议，不以一个综合分数判定所有作品。真实质量验收要观看完整影片，不能以四张抽帧代替动作、节奏和旁白检查。

## 6. 防止偏离初衷

新需求必须能回答至少一项：

1. 是否减少从创意到完整初稿的人工作业？
2. 是否提高失败后的恢复能力或费用可解释性？
3. 是否让局部精修更快、更便宜且不损坏已有作品？
4. 是否提升最终成片质量且有可验证证据？

没有明确贡献的需求进入候选池，不进入当前里程碑。新增模型、Agent 框架和 UI 面板不能作为里程碑本身。

暂不作为下一阶段目标：Kubernetes、微服务拆分、多租户、公网运营、ComfyUI、LangGraph、自动 VBench 排名选模、复杂专业剪辑器替代。

## 7. 决策权限与文档状态

用户已确认第 1 节产品原则。第 3 节默认值可在文档评审时调整；执行人员可决定私有函数、局部文件拆分和不影响契约的 UI 细节。

改变自动化程度、预算授权、数据保留、验收目标或支持用户范围，必须先记录范围变更并取得用户决定。目录结构或某个框架不应被当作不可变的产品要求。
