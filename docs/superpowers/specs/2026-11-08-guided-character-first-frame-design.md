# 引导式角色定妆与首帧设计

状态：用户已批准；尚未实施。

## 目标与边界

在现有 Python CLI/Core、FastAPI、React Studio、SQLite 和 FFmpeg 架构上，扩展引导式制作：根据故事提出角色和分镜草案，用户确认角色定妆及整份分镜，再逐镜生成和确认首帧，最后基于该首帧生成视频。现有素材、项目、SQLite、生成历史和 Director 报告均须保留；不继续开发 Director Continuity Agent。

## 故事、角色与分镜

- 大模型根据故事创意和项目总时长，一次提出角色建议与完整分镜草案。沿用现有 Dry Run、单次预算授权、Provider 时长校验及不明确请求的恢复机制。分镜草案始终可提前查看和编辑；不可因为已有草案而强制重新付费生成。
- 逐角色展示可编辑的角色设定、候选定妆照和确认状态。用户可上传自己的图片，或通过现有 OpenAI-compatible 图片服务单独授权生成；每次生成先 Dry Run，并单独确认正数预算。生成、上传或确认均不覆盖已有图片。
- 每个角色可保留多张候选和历史图，但同一时刻只选择一张已确认的主参考图用于首帧。角色文字设定和参考图须由用户确认；不声称模型可以保证角色一致性。
- 每张分镜卡片显示建议的出场角色，由用户增删修正；不能单纯靠提示词是否包含角色名来当作可靠关联。无角色镜头应可明确标记，以免强制关联无关角色。
- 先完成所有角色确认，再确认完整分镜；两者完成后才开放首帧生成。角色和分镜关联不完整时清楚提示，不能悄悄跳过确认。

## 首帧与视频

- 逐镜使用该镜头已确认的角色主参考图和分镜内容生成首帧。图片生成前提供 Dry Run，并要求每次明确授权预算；预算估算或预留不是供应商账单硬上限，失败也可能产生费用。
- 每次生成得到独立版本，用户预览并确认后，才允许生成该镜头的视频。失败、重试、更换选择和确认均不删除、不覆盖旧首帧或视频。
- 视频生成必须实际使用用户确认的首帧。按所选 Provider／模型验证图生视频能力和时长约束；若不支持或尚未核实，阻止生成并明确提示切换，不得静默退回文生视频。切换模型时重新检查既有分镜时长，不能悄悄改变分镜。
- 沿用现有逐镜完成、人工确认和渲染门槛，以及每次视频生成单独 Dry Run／预算授权。图片服务的无参考图角色生成与带参考图首帧编辑可能需要不同接口，必须核实所选服务和模型实际支持；未核实前不得假定可用。

## 版本变更与已有项目

- 更换已确认角色的主参考图时，该角色重新待确认。记录角色图、首帧、视频及镜头角色关联的版本来源；只标记受该角色影响的镜头，不影响无关镜头。
- 使用旧角色图生成的首帧标记“基于旧定妆”，须由用户重新选择并确认，或单独授权生成新首帧。旧首帧保留。
- 受影响镜头已有的已确认视频继续保留，不自动重生成；在最终渲染前用户须明确选择继续使用旧视频还是制作新版本。其他已确认镜头保持原有确认状态。
- 已有引导式项目可由用户主动启用此阶段，不自动迁移。保留已有分镜草案、已确认分镜、首帧与视频；展示现有信息供核对。如果需要额外 LLM 调用来建议角色或镜头关联，须先 Dry Run 并单独授权预算。启用后首次生成新首帧前，角色和整份分镜仍需完成人工确认。既有视频不得伪称使用了不可考证的首帧或角色版本；其来源未知时清楚标记。

## 实现和验收约束

- 现有 `guided_storyboard.py` 已返回 `character_bible` 和分镜草案，但尚无显式镜头角色关系；现有 `references.py` 的 manifest 只保存每个角色和镜头当前引用，不构成完整版本历史。须在复用既有逻辑的同时新增可追溯、向后兼容的版本和确认状态，不破坏 CLI 既有引用。
- 现有 `reference_generation.py` 仅使用图片编辑接口按镜头提示词匹配已导入角色，且要求至少一个匹配角色；它本身不能满足完整角色生成、显式关联、无角色镜头和历史版本要求。现有 MiniMax I2V 是独立实验，并非引导流程；不得误认为当前 Flux 文生视频已使用首帧。
- 用户上传图片应验证类型、大小和内容，安全保存到项目数据目录；不允许通过浏览器传任意服务器路径。每次 paid 请求须独立授权、持久记录，结果不明时禁止自动重复提交。前后端都需验证关键门槛，不依赖按钮禁用。
- 测试覆盖角色与草案持久化、上传与多版本选择、确认顺序、镜头角色关系、角色更换后精确影响范围、旧视频的明确选择、首帧和视频版本保存、Provider 能力拒绝、预算保护、并发／不明确提交和旧项目兼容。运行可执行的 Python 测试与 React 构建；明确指出未验证的浏览器与真实付费供应商流程。
- 不将 `.venv`、`.env`、`studio-data`、`node_modules` 或 `.git` 放入升级包；不读取或提交用户密钥。
