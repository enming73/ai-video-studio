# LLM 分镜与引导式制作流程设计

状态：用户已批准；实施与验证结果见本次工作区和测试记录。

## 目标与范围

在保留现有 Python CLI/Core、FastAPI、React Studio、SQLite 和 FFmpeg 架构的基础上，为新建项目增加引导式制作流程：LLM 按项目指定的总时长和故事内容规划分镜，用户逐卡审阅整份分镜，再逐镜生成、预览、确认，最后渲染。现有项目、CLI、原有渲染入口和数据不因引导流程改变；已有项目不自动迁入该流程。暂停 Director Continuity Agent 的进一步开发。

## 分镜规划与审阅

- `smart-plan` 不指定固定 `shot-length` 时，由 LLM 决定镜头数量和每个镜头的时长；指定固定时长的既有用法继续支持。
- 所有镜头时长之和必须精确等于项目总时长，且每个镜头须符合所选 Provider／模型已核实的时长约束。约束不可可靠确认时，提示用户并阻止依赖该约束的付费请求，不猜测。调用 LLM 前检查总时长是否存在可行分配；返回后及每次编辑后再次校验。不合格结果不作为已确认分镜保存，不悄悄修改时长。
- 先 Dry Run，再针对每次付费 LLM 分镜请求单独提供明确预算并确认授权。预算估计或预留不声称是供应商账单硬上限；向供应商发送的内容和可能产生的费用应明确展示。
- LLM 返回后，以独立镜头卡片展示完整分镜，支持逐镜编辑描述、调整时长以及增删镜头，不要求用户编辑 JSON。展示项目目标总时长、当前合计和约束错误。用户确认完整分镜后才能进入逐镜制作。
- 草稿和确认操作须保护现有分镜、素材和历史记录；失败、无效结果或取消不得覆盖已有数据。

## 逐镜制作和渲染

- 界面采用纵向步骤：创建项目 → 分镜审阅 → 逐镜制作 → 渲染。逐镜制作聚焦当前镜头；当前镜头须有可预览的视频并经用户确认，才可进入下一未处理镜头。
- 每次视频生成或重新生成先 Dry Run，再单独确认预算和授权。生成成功不等于确认；用户可预览、修改提示词、重新生成和选择旧版本。所有生成素材应保留，不因重新生成、选择、确认或渲染而覆盖或删除；删除只可由用户主动操作，具体删除入口不在本设计中假设已存在。
- 用户可以返回已确认的镜头。修改该镜头描述或切换视频版本会使该镜头重新待确认；仅查看不改变确认状态。后续已确认镜头保持确认，不要求重新确认。
- 在引导流程中，只有所有镜头均有当前有效确认时才能 Render；后端也须检查，不能仅依赖界面禁用。原有项目和原有渲染入口保持兼容。
- 新流程的草稿、镜头进度、确认及素材版本应持久保存，服务重启后可恢复；避免对结果不明确的付费任务自动重复提交。

## 实现边界与验证

- CLI/Core 为业务逻辑中心，Web API 复用核心逻辑；SQLite 修改须向后兼容、非破坏性，保留数据库、素材、生成历史和 Director 报告。现有 `shots`、素材登记和渲染机制如何安全支持独立版本与确认状态，实施前需检查并设计迁移及文件写入方式。
- 当前 `smart-plan` 没有预算门控，浏览器 Plan 调用 `core.plan` 而非 `smart-plan`；不能把新增流程的预算保护误认为现有所有付费入口都已安全。设计及测试必须覆盖实际涉及的付费入口，不自动调用付费服务。
- Provider／模型的时长能力、预算估算方法、外部接口和模糊提交恢复能力须在实施时依据实际源码及可信供应商资料核实。估算不可用时不得伪称已知费用或硬性花费上限。
- 代码变更后运行可执行的 Python 测试和 React 构建，并明确说明未验证的浏览器、FFmpeg 或真实供应商端到端部分。升级包排除 `.venv`、`.env`、`studio-data`、`node_modules` 和 `.git`。
